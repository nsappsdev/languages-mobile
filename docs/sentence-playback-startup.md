# Sentence playback startup — 2026-11-16

The reader prepares the current sentence when a lesson opens and keeps two sentences ahead. Each sentence contains its natural reading, contextual word repetitions, pauses, and any Deep Learning sentence replays. Expo Audio's playlist advances between these prepared files; preparation of later sentences does not block Play. Other enabled modes are warmed at the current sentence, and mode changes reuse their prepared files and loaded players.

Pause/resume retains the same playback position, including a pause between repetitions. Seeking maps the lesson timeline into the first natural pass of the requested sentence. A failed download stops at that sentence and can be retried without skipping it. Leaving the reader cancels preparation and releases players and temporary files.

Source recordings remain authenticated and account-scoped. Cache identity includes the API server, account, asset ID, and SHA-256, so an unchanged recording can be reused after republishing while a changed recording gets a new key. Native devices use the private cache directory; web now also uses Cache Storage so downloads survive a page reload. Logout clears audio storage. Source memory has a 96 MiB budget (with a minimum of three recent items), persistent source storage has a 256 MiB target, and prepared segments have a 64 MiB/48-entry target. Active segments are retained until released; browser quota failures fall back to memory.

This is an opportunistic cache, not a complete offline lesson download. Opening a lesson still requires its manifest/settings. A first visit or a jump outside the prepared window can wait for that sentence; poor connectivity can still interrupt playback, and the OS/browser may evict cached files. Legacy publications with one full narration remain compatible and cannot gain the same sentence-download benefit.

Validation: 128 Jest tests, TypeScript, Expo lint, and web production export passed. Tests cover slow and failed downloads, ordered queue growth, mode reuse, native seek completion, latest-selection cancellation, bounded queues, end-of-queue progress, cache invalidation, and storage failures. The local “14 law” browser preview confirmed persistent source-cache hits after reload, mode switching, seeking, and playback. Development-only logs report time from the Play handler to the first observed playback-clock advance; they measure application startup, not speaker output. A physical Android/iOS device and release-build timing still need verification. No store build or deployment is included.
